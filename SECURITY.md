# Security policy

## Supported versions

Security fixes are applied to the latest published version.

## Report a vulnerability

Do not open a public issue for a vulnerability that could expose credentials, execute unintended commands, escape configured paths, or compromise release artifacts.

Use the private vulnerability reporting feature in the GitHub Security tab when it is enabled. If private reporting is unavailable, contact the repository owner through the contact method listed on the GitHub profile.

Include a concise description, affected version, reproduction steps, impact, and any suggested mitigation. Remove real tokens, account identifiers, and personal data.

## Scope

Useful reports include command execution boundaries, subprocess cleanup, file permissions, configuration writes, asset protocol scope, release provenance, signing, and provider response validation.

Provider service outages, delayed provider accounting, and unsupported third party API behavior are reliability concerns unless they create a security impact.
